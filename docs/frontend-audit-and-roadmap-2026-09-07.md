# 前端核查与后续发展计划

核查日期：2026-09-07。基准：`main` / `f40701f`，项目版本 `0.8.0`。
核查对象是当前完整工作树，不是某次提交引入的回归。开始核查时工作树干净。
以下核查与计划记录修复前的状态；当时未修改应用代码、内容、依赖或发布配置。
用户随后授权实施修复，F1–F9 的处理与验证结果见文末“修复验收记录”。

## 结论

现有页面结构、共享组件与主要交互可以继续沿用。当前演示内容下没有发现全站不可用、
主导航失效或大面积布局溢出的 P0 问题，但存在 **4 项 P1、5 项 P2**。
最需要先处理的是内容被静默遗漏或错配，以及深色模式的重要文字不可读。

当前问题主要暴露在真实内容替换与可选配置上：示例页面正常，并不能证明模板对作者的
常见操作同样可靠。下一阶段应先修复并建立这些边界的回归检查，再扩展功能。

本报告使用：P0＝现有主要流程普遍阻断；P1＝内容完整性、构建或明显可读性问题，
应在下次发布前解决；P2＝有替代路径或影响有限，但应排入后续修复。
条件触发的问题不等于当前演示站已经出现对应故障。

## 详细发现

### F1 · P1 · BibTeX 注释导致论文丢失或标题与引用键错配

位置：`src/lib/bibtex.ts:206`；影响 `src/lib/papers.ts` 的所有调用者，包括首页和 Research。

条目正则要求结束大括号后只出现空白，然后紧跟下一个 `@` 或文件结尾。
条目之间出现注释时，它会跨越真正的条目边界，把两个条目作为一个解析；后一个字段覆盖前一个字段。
文件末尾出现注释时，最后一个条目也可能完全不匹配。

已运行以下输入：

```bibtex
@article{one,title={One},year={2024}}
% between entries
@article{two,title={Two},year={2025}}
```

预期：两条论文。实际：只有一条，`id="one"`、`title="Two"`、`year=2025`。
单条论文后追加 `% file comment` 时，实际返回空数组。
这会污染论文清单和复制出来的引用，构建却未必报错。

建议：在共享解析器中按括号深度、引号与注释识别条目边界；解析不支持的输入时给出明确诊断。
不要只在首页或 Research 增加显示层补丁。保留一组小型输入/输出回归用例，
至少覆盖条目间注释、末尾注释、嵌套括号与多个条目的 ID/标题对应关系。

### F2 · P1 · 缺失 `accent-950` 使深色模式出现浅底浅字

位置：`uno.config.ts:221` 的 `accent` 色表仅定义到 900；
使用处包括 `src/pages/teaching.astro:69`、`:126`、`src/pages/index.astro:119`、
`src/pages/about.astro:122`、`:170` 以及论文与课程行的 hover 样式。

生成 CSS 中不存在 `bg-accent-950`。深色教学页课程编号实测为：

```text
color: rgb(191, 216, 223)
background-color: rgba(238, 245, 247, 0.7)
font-size: 13px
```

深色文字变体生效，但背景仍沿用浅色模式。以当前暗色父背景进行合成估算，
文字对比度约 1.4:1；截图中课程编号和首页状态徽章都明显难读。
普通小字号文本的参考要求为 4.5:1，见 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

建议：在共享主题中补齐需要的色阶，或统一替换为已有且满足对比度的色阶；
一起核查静止与 hover 状态。验收应同时检查生成 CSS 和浏览器计算颜色，
不能仅断言源码包含 `dark:` 类名。

### F3 · P1 · 文档声明支持 MDX，但 MDX 文章被跳过

位置：`src/content.config.ts:19`、`astro.config.ts:10`、`package.json`；
对应承诺见 `README.md:97`、`README.zh-CN.md:88`。

loader 接受 `*.mdx`，但项目没有安装或注册 MDX integration。
在隔离副本中把 `grant-update.md` 改为 `grant-update.mdx`，实际输出：

```text
[WARN] [glob-loader] No entry type found for grant-update.mdx
[build] 19 page(s) built
[build] Complete!
```

原本 20 个页面变成 19 个，文章不再进入清单和详情路由，构建返回成功。
对此产物运行现有 `assert-built-site.mjs` 也通过，说明它没有检查作者内容是否全部被生成。

建议：按当前公开承诺接入官方 MDX integration，并用包含实际 MDX 语法的条目验证；
若产品决定仅支持 Markdown，应同步收窄文档和 loader，并明确拒绝 MDX，不能继续静默遗漏。
官方接入方式见 [Astro MDX 文档](https://docs.astro.build/en/guides/integrations-guide/mdx/)。

### F4 · P1 · 递归内容目录与单段详情路由不兼容

位置：`src/pages/posts/[slug].astro:11`；同类结构也存在于
`src/pages/projects/[slug].astro:8` 和 `src/pages/teaching/[slug].astro:12`。
三个 loader 都使用递归 glob。

隔离副本中将 `src/content/posts/grant-update.md` 移到 `src/content/posts/2024/grant-update.md`，
内容 ID 变为 `2024/grant-update`，但路由仍为单段 `[slug]`。实际构建失败：

```text
Caught error rendering /posts/2024/grant-update:
TypeError: Missing parameter: slug
```

这会阻断整站构建。博客路径已实际复现；项目和教学根据相同的 loader / ID / 路由流程判断有同类风险，
尚未分别执行移动文件实验。

建议：使用能够承接多段 ID 的 `[...slug]` 路由，保留原有平铺 URL；
同时把构建产物检查中的单层目录枚举改为递归检查。
若明确只允许平铺目录，则在内容入口拒绝子目录并给出作者可理解的错误。

### F5 · P2 · 引用导出丢失原始字段，并可能拆错组织作者

位置：`src/lib/bibtex.ts:59`、`:129`、`:144`、`:228`。

输入包含 `volume={12}`、`number={3}`、`pages={20--30}`、`doi={10.1234/test}` 的文章后，
解析后的数据和导出的 BibTeX 都没有这些字段。`{DNA}` 的大小写保护括号也被去掉。
组织作者 `{{Research and Development Group}}` 会被拆成两位作者，
APA 输出出现 `Research, & Group, D.`。

建议：保留原始 BibTeX 条目供 BibTeX 复制使用，将展示所需字段与无损原文分开。
组织作者、姓名前缀与后缀不能从已经扁平化的展示名字可靠恢复。
当前姓名拆分代码已注明简化边界，应让产品承诺与该边界一致；
在宣称完整标准引用之前，补上结构化作者和文献字段的验证。

### F6 · P2 · 空论文库能构建，却无法通过现有验证

位置：`scripts/assert-built-site.mjs:170`，相关显示逻辑在 `src/pages/researches.astro`。

隔离副本中将 `src/data/publications.bib` 清空，20 个页面仍成功构建；
随后构建产物检查失败：

```text
Error: research categories should use the shared publication list
```

作者还没有论文，或先清理演示内容时，会遇到这个问题；CI 及调用验证的模板更新流程因此被阻断。
Research 当前也没有“暂无论文”之类的可见空状态。

建议：让检查区分合法空集合与渲染失败；有内容时要求清单，无内容时验证明确的空状态。
不要为了让断言通过而插入空的论文列表。同步加入全草稿、仅一类论文等边界用例。

### F7 · P2 · 精选文章没有封面时，桌面仍保留空图片列

位置：`src/components/PostCard.astro:30`、`:35`、`:57`。

移除精选文章的 `heroImage` 和 `heroImageAlt` 后，构建正常，
但 `featured` 仍无条件开启两列 grid。1280 CSS px 下的实际布局：

```text
cardWidth: 948px
gridTemplateColumns: 412.2px 503.8px
imageCount: 0
onlyChildWidth: 412.2px
```

正文挤在左列，右侧约 504px 空白；长标题因此多换行。
封面本来是文档明确支持的可选字段，所以这属于缺少无封面变体。

建议：只有有封面时开启双列布局；无封面时让文字占用合理阅读宽度。
首页项目卡片也有按固定图片列构建的结构，可在同一轮核查其无封面状态，尚未计为独立实测缺陷。

### F8 · P2 · 引用弹窗没有可访问名称

位置：`src/components/PublicationList.astro:125`。

`dialog` 既没有 `aria-label`，也没有关联标题的 `aria-labelledby`。
浏览器无障碍树中只显示无名称的 `dialog`，而不是“Cite this paper”。
关闭按钮、原生模态行为和 Esc 后焦点返回正常。

建议：为可见标题生成与 dialog ID 配套的唯一 ID，用 `aria-labelledby` 关联；
必要时再关联论文标题。可参考 [W3C 模态弹窗命名模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。
验收重点是 dialog 的计算名称，而不是页面上是否存在一个可见 h3。

### F9 · P2 · 封面直接输出原图，未获得实际图片优化

位置：`src/components/PostCard.astro:44`、`src/pages/posts/[slug].astro:106`、
`src/components/DetailShell.astro:67` 以及首页/项目页封面。

这些位置使用 `<img src={image.src}>`。现有三张博客图片在 `dist` 中与源文件
SHA-256 完全相同，没有 `srcset` 或根据显示尺寸生成的版本：

| 图片 | 单文件大小 |
| --- | ---: |
| fictional-scholars-site.jpg | 537,355 bytes |
| synthetic-bibliography.jpg | 436,851 bytes |
| imaginary-workshop.jpg | 412,694 bytes |

三张合计 1,386,900 bytes；存在 lazy loading，因此不能把总数当作首屏下载量。
窄屏仍会下载同一张完整原图。README 中“交给 Astro 优化”的描述与当前产物不一致。

建议：复用 Astro 已有的 `Image` / `Picture` 能力，为卡片和详情设置实际需要的尺寸及 `sizes`；
保留当前 alt、宽高和优先级设置。参考 [Astro 图片文档](https://docs.astro.build/en/guides/images/)。
验收检查实际输出格式、宽度与请求字节数，不只看导入路径是否位于 `src/assets`。

## 后续如何持续检测

保留 `pnpm verify` 作为入口，补齐它现在无法观察的三个层面：

1. **源内容与产物对应**：每条非草稿内容都应有详情页，并出现在适当的索引中；
   页面数不能硬编码成演示站的 20。对未知扩展名、重复 ID、无法解析条目给出明确失败原因。
2. **真实交互与样式结果**：用一个小型浏览器冒烟流程验证菜单、主题、筛选、弹窗、复制状态、
   焦点返回、详情往返；检查可访问名称、计算颜色和实际溢出。
3. **代表性边界内容**：空集合、单条内容、全部 draft、有/无封面、子目录、MDX、
   长标题、中文、长链接、表格和代码块。每类保留最小样例，修复时立即加入对应回归，
   不复制一整套演示站维护第二份内容。

| 检查时机 | 最小检查集合 | 失败时的动作 |
| --- | --- | --- |
| 每个修复 PR | 对应失败用例 + 原有 verify | 阻止该修复进入发布 |
| 修改共享布局、CSS、脚本 | 桌面/移动、浅色/深色的代表页面 + 关键浏览器流程 | 保存实际尺寸、截图和操作序列，按同一根因合并处理 |
| 修改内容格式、loader、路由 | 非草稿内容与产物映射 + 空内容 + 子目录/MDX | 报告具体源文件；区分不支持与数据错误 |
| 发布前 | 在 Node 24 和干净安装环境复核；覆盖项目支持的浏览器；检查生产 URL | 不把本地样例通过视为跨环境验证通过 |
| 上线后 | 真实断链、资源错误、页面性能与读者任务反馈 | 由实际问题决定下一轮功能，不先引入完整监控平台 |

## 分批发展计划

下面的工作量顺序是依赖关系，不是已承诺工期。每批修复都应同时提交最小回归检查。

| 批次 | 目标与具体工作 | 完成条件 |
| --- | --- | --- |
| A1：内容可靠性 | F1 BibTeX 边界；F3 MDX 支持与文档一致；F4 递归目录与路由一致 | 论文 ID/标题不串；MDX 内容能实际进入页面；子目录条目生成正确 URL；现有平铺链接保持有效 |
| A2：可读性与内容变体 | F2 主题色阶；F7 无封面布局；F8 dialog 名称 | 所有相关深色标签与 hover 可读；无封面精选无空列；弹窗有计算名称且保持焦点返回 |
| B：作者工作流 | F5 原始引用保真；F6 空集合；内容数量与产物对应检查；同步 README/authoring 中的真实支持范围 | 作者可移除演示内容并逐条新增；合法空站不会被误判；引用不丢关键字段；遗漏内容必被检查发现 |
| C：图片与发布体验 | F9 使用已有图片能力；补齐代表页面的尺寸/资源预算；执行跨浏览器和干净环境验证 | 实际生成适配尺寸的图片；用同一页面与网络条件比较请求量；完整验证和浏览器冒烟均通过 |
| D：由真实使用决定增量功能 | 观察作者维护与读者查找任务，再选择下一项小功能 | 每项新需求都有具体用户任务、成功指标和继续维护成本的依据 |

批次 D 建议从三个实际任务收集证据：

- 作者：替换身份资料、添加一篇真实结构的论文、发布一篇无封面文章、添加同课程的新学期。
  记录失败步骤、难以理解的字段与重复修改，优先改善校验信息和作者文档。
- 读者：找到某篇论文并复制引用、找到当前课程及资料、判断项目的状态与贡献。
  如果现有分类无法完成查找，再增加标题/作者关键词搜索；无需先引入外部搜索服务。
- 维护者：从当前版本升级且保留个人内容、在支持的部署目标生成正确 URL。
  以真实升级样例决定是否扩展迁移检查，而不是继续堆叠配置选项。

RSS、全文搜索、标签聚合、中文界面、CMS 等都可作为候选；
分别应由持续订阅需求、内容规模/查找失败、标签使用、语言用户和多人编辑需求触发。
